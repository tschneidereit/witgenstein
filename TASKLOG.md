## Proc-Macro Migration

- [x] **Replace CLI with `component!` proc macro** (2026-04-13): Removed `crates/witgenstein-rs/` CLI tool entirely. Rust component generation is now done via the `component!` proc macro in `witgenstein-rs-macros`. The macro parses `#[export]`-annotated items with `syn`, generates inline WIT, and emits `wit_bindgen::generate!` glue — all at compile time. Users just `cargo build --target wasm32-wasip2`. Added `extract.rs` (AST-based type extraction), `wit.rs` (inline WIT generation), `glue.rs` (wit-bindgen glue code generation). Configurable via inner attributes: `#![package("ns:name@ver")]` and `#![interface("name")]` with sane defaults. Glue code is cfg-gated to `wasm32` so native `cargo test` works. Added 3 test fixtures (component-basic, component-types, hashtools) and 20 integration tests with wasm-tools validation and wasmtime runtime tests. Updated hashtools sample to use `component!` with custom package/interface config. 57 total tests pass, zero clippy warnings.
- [x] **Source-scanning type discovery** (2026-04-13): Types (structs, enums) no longer need to be inside `component!`. The macro now reads the crate's source files via `CARGO_MANIFEST_DIR/src/` at expansion time using `syn::parse_file`, collecting all struct/enum definitions. Types in exported function signatures are automatically resolved from this scan — including transitive references (e.g. a record field that is itself an enum). Types inside the macro still work and take precedence. Updated all samples (hashtools, textkit) and the component-types fixture to define types outside the macro. Fixed `discover_type` to skip resource types (avoids spurious record typedefs for types that are `#[export] impl`'d as resources). Updated README, SPECIFICATION.md. All 102 tests pass, zero clippy warnings.
